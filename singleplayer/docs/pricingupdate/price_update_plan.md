# Price Update Plan

* We are updating the following file only: /home/nate/Desktop/git/ffxi-ashita/config/autoitem/items.csv
* The table below specifies how to compute the price_single value for items in each file, and each file can be found in the same dir as this md
* The table below may reference an hq multiplier, this can be determined by the highest skill level value of the synth, which can be derived from the recipes.lua file:
    * 90+: 30
    * 70-89: 15
    * 50-69: 7
    * 1-49: 3
    * E.g.
        * Wood 16 -> 3
        * Gold 67 -> 7
        * Wood 76, Smith 43, Cooking 11 -> 15
        * Gold 96 -> 30
* The table below may reference an nq divisor, this can be determined by the highest skill level value of the synth:
    * 90+: 2
    * 70-89: 3
    * 50-69: 4
    * 1-49: 5
    * E.g.
        * Wood 16 -> 5
        * Gold 67 -> 4
        * Wood 76, Smith 43, Cooking 11 -> 3
        * Gold 96 -> 2
* Important: Be mindful that some synths produce more than 1 quantity and the recipes.lua should have this information, many types of arrows are an example of this, so in the table below when we say sum the cost of the ingredients, we mean that on a per item basis, so if the synth produces a quantity of 3, then we divide the sum of the ingredient cost by 3 to get the per item ingredient cost
* For the row updates in items.csv:
    * The table below will provide instructions on how to determine the new price_single
    * price_single is the price of a single item, and price_stacks is the price of a stack of items, and we want to update both, and we will not be updating any other values in any row
    * If price_stacks is equal to 1, this means that the item is not stackable and there is no need to update the price_stacks value
    * When price_stacks is greater than 1, it is either 12 times the existing price_single or 99 times the existing price_single
    * When we update the price_single value, we want to determine if the price_stacks is price_single times 99 or price_single times 12, and then update the price_stacks with a new value found by multiplying the new price_single by either 12 or 99, whichever was used before
    * We are not updating any rows that have sell_single=1, so those row values will remain the same -- this should not be encountered, but we should guard against it and log when found
* If you cannot determine definitively the new price_single for some reason, then please make a note of it to provide a list of these as output
* Process the files in the order in the table, as some files rely on results from rows above
* Do not change the order of rows within the items.csv file, the order should stay the same, we are just updating row values
    * This is a point of emphasis, the items.csv file has been heavily edited manually by a human, the items are grouped up together by their own category types and are in a familiar order to the human, and changing the row order would confuse the human in the future
* All of these files in the table below have the same format except for conquest_items.csv, which as it own special format different from the other.
    * So there are two different formats, the one in conquest_items, and the format used for all the others
* Output should include all items not processed for any reason stored in an md file broken down by which file they were from
