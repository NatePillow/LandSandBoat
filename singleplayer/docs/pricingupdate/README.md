# Items Price Pipeline — Scripts Reference

Run from the **repo root** (`/home/nate/Desktop/git/ffxi-ashita`):

```
python3 docs/items/scripts/run_pipeline.py [--lsb /path/to/LandSandBoat]
```

Default LSB path is the sibling directory `../LandSandBoat`.

---

## What the pipeline does

Updates `config/autoitem/items.csv` with computed `price_single` and `price_stacks`
values for every item that can be priced from recipes, mob drops, or conquest rewards.
Outputs a skipped-items report to `docs/items/price_update_skipped.md`.

---

## Pipeline steps (run_pipeline.py)

| Step | Script | Output |
|------|--------|--------|
| 1 | `generate_recipes.py` | `config/autoitem/recipes.lua` |
| 2 | `extract_craftable_items.py` | `docs/items/csv/update_items.csv` |
| 3 | `extract_equipment.py` | `docs/items/csv/equipment/equipment.csv` |
| 4 | `extract_mob_levels.py` (non-equipment) | `docs/items/csv/drops_items_non_equipment_mobs.csv` |
| 5 | `extract_mob_levels.py` (equipment) | `docs/items/csv/drops_items_equipment_mobs.csv` |
| 6 | `extract_conquest_items.py` | `docs/items/csv/conquest_items.csv` |
| 7 | `remove_conquest_items.py` | edits all split CSVs in-place |
| 8 | `update_prices.py` (pass 1) | `config/autoitem/items.csv` |
| 9 | `update_prices.py` (pass 2) | `config/autoitem/items.csv` |
| 10 | `update_prices.py` (pass 3) | `config/autoitem/items.csv` |

Steps 1–7 refresh data from LandSandBoat. Steps 8–10 compute prices.

### Why update_prices.py runs 3 times

The pricing pipeline has multi-level ingredient dependencies. Items computed in an
earlier step become ingredient costs for items computed in later steps — but only
if their prices are already in `items.csv` at the start of the run.

- **Pass 1**: prices items whose ingredients are all NPC-buyable (sell_single=1)
- **Pass 2**: ~565 items (mostly HQ +1 equipment) reprice using pass 1 computed costs;
  some jump dramatically (e.g. 24K → 5.8M) because their NQ ingredient is now correctly priced
- **Pass 3**: 3 remaining items converge due to within-file ordering; pass 4 is identical

After 3 passes the output is fully stable. If you only changed item prices or recipes,
you can run `update_prices.py` 3 times manually instead of the full pipeline.

## Static split CSVs (do not delete — not regenerated by pipeline)

These files in `docs/items/csv/` were built manually/collaboratively and categorize
items for pricing. They are read by `update_prices.py` and `remove_conquest_items.py`
but **never overwritten** by the pipeline. If new items are added to the game,
these files need to be manually updated.

### Category breakdown

Items with `sell_single=0` in `items.csv` (not NPC-sold, need computed prices) are
split into tiers based on whether their recipe ingredients are NPC-buyable:

| Prefix | Meaning |
|--------|---------|
| `update_items_*` | All recipe ingredients have `sell_single=1` (fully NPC-buyable) |
| `craftable_buyable_items_*` | Mix: some ingredients NPC-buyable, some from AH/drops |
| `craftable_items_*` | All ingredients from AH/drops (no NPC-buyable ingredients) |
| `drops_items_*` | Items obtained from mob drops (not crafted) |

Each prefix has equipment and non-equipment variants, and NQ/HQ/NQ-only sub-splits:

| Suffix | Meaning |
|--------|---------|
| `_nq` | NQ result of a recipe that also has an HQ version |
| `_nq_only` | NQ result of a recipe with no distinct HQ item |
| `_hq` | HQ result items |

## Price formulas (update_prices.py)

### Skill-based factors
Determined by the highest skill level in the recipe:

| Max skill | NQ divisor | HQ multiplier |
|-----------|-----------|---------------|
| 90+       | 2         | 30            |
| 70–89     | 3         | 15            |
| 50–69     | 4         | 7             |
| 1–49      | 5         | 3             |

### Per-category formula

| Category | Formula |
|----------|---------|
| `update_items_*_nq` | sum(ingredients) / nq_divisor |
| `update_items_*_nq_only` | sum(ingredients) |
| `update_items_*_hq` | sum(ingredients) × hq_multiplier |
| `craftable_buyable_*` / `craftable_items_*` | same formulas, but ingredients may include non-NPC items whose prices were computed earlier in the run |
| `drops_items_non_equipment` | level × 100 (normal/mixed) or level × 1000 (nm_only); level = midpoint of min/max mob level; 50000 for bcnm/enm or missing levels |
| `drops_items_equipment` | level × 1000, then × mob_type multiplier: nm_only ×5, bcnm/enm/isnm ×10, normal/mixed ×1 |
| `conquest_items` | cp × 10 |

Multi-output recipes: ingredient cost is divided by `qty` before applying the formula.

### Stack price detection
When `price_stacks > 1`, the script detects whether it's `12 ×` or `99 ×` the
existing `price_single` and updates accordingly. `price_stacks = 1` means
non-stackable — left unchanged.

Items with `sell_single=1` are never updated.

## Desynthesis exclusion

Desynthesis recipes are identified by: **lightning crystal (id 4100) + single ingredient**.
These are excluded from the recipe graph when computing prices. Without this exclusion,
circular dependencies between items (e.g. mythic_wand ↔ phoenix_feather, shofar ↔
behemoth_horn, galateia ↔ blessed_bliaut) cause exponentially inflating prices across runs.

**Do not remove this exclusion.** The fix is in `parse_recipes()` in `update_prices.py`:
```python
if crystal == 4100 and len(ingredients) == 1:
    continue
```

---

## Multi-variant recipe handling

Some items have multiple recipe variants. The script picks the variant with the
fewest unique missing ingredient IDs (`best_variant()`). This ensures kit-based
shortcut recipes (e.g. bonecraft kit 95) are deprioritized in favor of the real recipe.

---

## Missing ingredients

When an ingredient has no price in `items.csv`, the item that needs it is skipped.
Skipped items are reported in `docs/items/price_update_skipped.md` with the missing
ingredient IDs and names.

A deduplicated list of missing ingredient IDs/names is in `docs/items/missing_ingredients.md`.
To add a missing ingredient: find its market price, add it to `items.csv`, then re-run
`update_prices.py`. This will unlock pricing for all items that depend on it.

The missing ingredients list is at `docs/items/missing_ingredients.md`.
The skipped items report is written to `docs/items/price_update_skipped.md` after each run.

---

## Resetting items.csv

If `items.csv` gets corrupted (e.g. outlier prices in the billions), reset it with git:
```
git checkout config/autoitem/items.csv
```
Then re-run the pipeline. Do NOT run the pipeline multiple times on a corrupted
`items.csv` — circular dependency items will inflate exponentially on each run.

---

## Outlier detection

After running, check for suspiciously large prices:
```
awk -F',' 'NR>1 && $5+0 > 10000000 {print $1, $2, $5}' config/autoitem/items.csv | sort -k3 -rn
```
Legitimate items can exceed 10M gil (e.g. expensive HQ gear with rare ingredients).
Circular dependency corruption typically shows values in the billions.

## items.csv format

```
itemid, name, sell_single, buy_single, price_single, stock_single, sell_stacks, buy_stacks, price_stacks, stock_stacks
```

- `sell_single=1`: item sold to NPCs — **never updated by pipeline**
- `price_stacks=1`: item not stackable — stack price left unchanged
- Row order is manually curated — **never reorder rows**
